总体架构

三级结构：采集、汇聚、集中监控

第三层 L3
星闪采集节点
连接 IMU、电机、电流、电压、温度等传感器，完成采样与基础校验。
→
第二层 L2
星闪汇聚控制器
通过 SLE 汇聚 L3 数据，统一补充 l2_id、seq、CRC 后上报。
→
第一层 RK3506
UDP Receiver + TUI
解析 UDP 帧、维护状态快照、提供低资源 TUI 看板。
L2-1第二层星闪汇聚控制器编号，来自 UDP FrameHeader.l2_id。
L3-11第三层采集节点编号，来自 SENSOR_DATA / NODE_INFO payload。
S10007传感器编号，同一个 L3 下唯一，用于区分 IMU、电机、电池等节点。
L2-1/L3-11/S10007完整节点 key，由 l2_id + l3_id + sensor_id 组成，保证节点可检索、可更新、可删除。

数据协议

统一 UDP 数据帧：轻量、可校验、可扩展

36 字节 FrameHeader

  • l2_id：L2 身份统一进入帧头。
  • seq：支持丢包、乱序、重复包判断。
  • payload_len：业务数据边界明确。
  • payload_crc32：先校验，后解析。
Headermagic / version / msg_type / l2_id / seq / timestamp / len / crc32
PayloadL2_HELLO、L2_HEARTBEAT、NODE_INFO、SENSOR_DATA
State按 l2_id + l3_id + sensor_id 生成唯一节点 key
key = (FrameHeader.l2_id, payload.l3_id, payload.sensor_id) SENSOR_DATA: data_type = IMU / MOTOR / CURRENT / BATTERY ... array_count = scalar: 1, compound: N arrays = repeated metric arrays
星闪优势

星闪一对多：让无线侧承担节点扩展

L2 汇聚带来的价值

  • RK3506 不直接管理每个无线节点，系统复杂度更低。
  • L2 就近汇聚 L3 数据，统一节点编号和状态。
  • 多 L2 扩展时，RK3506 仍沿用同一 UDP 协议。

星闪链路价值

  • 适合近距离、低功耗、低时延设备互联。
  • 一对多拓扑清晰，适合传感器节点扩展。
  • 与 RK3506 组合后，形成国产化采集监控闭环。
